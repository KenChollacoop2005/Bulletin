Procedural generation & pathfinding

01

Runtime content generation implemented from first principles — connectivity-guaranteeing random walks, specialized shortest-path search, and graph reachability analysis, applied here to dungeon layout.

board_gen.py

Constructive random-walk generation with a provable connectivity invariant

Rather than sampling wall/floor noise per-cell and hoping the result holds together, this generator builds connectivity as an invariant of the algorithm itself: every new cell is carved adjacent to an already-connected cell, so the region is guaranteed connected by construction — no flood-fill validation pass required, no retry loop needed to reject a broken layout. A directional-bias term (a 15% weighted step toward a target) keeps the walk convergent without collapsing into a straight line. Applied here to carve the game's dungeon floors.

max_steps = width × height × 40, with a guaranteed L-shaped fallback corridor if the walk never converges.
board_gen.py

0-1 BFS shortest-path search (deque-based Dijkstra specialization)

Implemented a specialized graph-search algorithm for 0/1-weighted edges — pushing zero-cost transitions to the front of a deque and unit-cost transitions to the back — which recovers Dijkstra's correctness guarantee in linear time, without the O(log n) overhead a general priority-queue implementation would require. Used here to compute minimum-cost repairs when generated dungeon regions become disconnected.

Used to surgically reconnect any floor pocket orphaned by softlock-prevention widening, repeated to a fixed point.
floor_gen.py

Directed-graph modeling with a dedicated reachability/depth analysis pass

Runtime content is generated by first building and validating a directed graph data structure, independent of any visual representation — nodes carry no inherent notion of distance from the root, since insertion order and traversal order are two different orderings entirely. A separate breadth-first search computes true graph-theoretic depth per node, which a content-placement policy then consumes as a hard constraint. Applied to dungeon layout, this guarantees a rule holds regardless of which of two branch paths gets taken.

Powers a hard rule: no dangerous enemy can spawn inside the first two rooms, on either branch path, regardless of which one a run takes.
landmark_rooms.py

Procedural silhouette generation via additive harmonic synthesis

A closed-form irregular boundary is generated by summing multiple sinusoidal harmonics (independently randomized amplitude, frequency, and phase) around a base radius — the same additive-synthesis principle used to build complex waveforms from simple ones, applied here to geometry instead of audio. Produces a naturalistic, non-repeating silhouette from a handful of parameters rather than a hand-authored shape or expensive noise field.

radius(θ) = base_radius + Σ harmonic_i.amp · sin(harmonic_i.freq · θ + harmonic_i.phase)
landmark_rooms.py

Parametric curve authoring to eliminate a systemic visual defect

Diagnosed a recurring visual-quality complaint down to its root geometric cause — straight-line segments reading as artificial — and replaced the underlying primitive with quadratic Bézier curves bowed through a control point, the standard technique for authoring organic curvature in any 2D graphics pipeline. Applied to a set of hand-authored anatomical templates for an in-game puzzle.

One rib-like candidate per template is always rendered pre-broken — fractures are guaranteed, not possible.

Deterministic seeding & hidden-math design

02

Reproducible-by-construction randomness engineering: a full simulation state rebuilt deterministically from a single string input, with exploit resistance designed in at the architecture level rather than patched after the fact.

seed_engine.py

Deterministic PRNG seeding from arbitrary input

A custom string-hashing function maps arbitrary player-supplied text to a seed for a PRNG instance, and every downstream subsystem draws from its own independently-salted stream rather than sharing one global generator — the standard technique for keeping unrelated random draws from perturbing each other. The result: fully reproducible, shareable output from a single opaque string input, applied here to dungeon generation.

Independently-salted RNG streams per subsystem (layout, enemies, events) so one draw never perturbs another.
seed_engine.py

Ensemble scoring over free-text input

Free-form user text is scored by one of several independent, randomly-selected feature extractors (lexical counts run over the input), then reduced into a bounded outcome space via modular arithmetic — a lightweight ensemble technique that stays deterministic per session while keeping the exact decision function opaque to the end user by design.

Deterministic per playthrough; unguessable in practice, with zero fairness bias against long or short answers.
seed_engine.py

Closing an exploit at the design layer, not the patch layer

Identified and pre-empted a class of exploit before it could ever ship: any system where a deterministic input can bias an outcome risks that input being farmed for a guaranteed result. Solved by architecturally separating "odds computation" (deterministic, derived from input) from "outcome roll" (non-deterministic, real entropy) — a pattern borrowed from how a fair gambling system separates house-edge configuration from the actual random draw.

chance = 0.05 + 0.30 × (vowels / letters) — nudgeable, never guaranteed.

Simulation engineering & self-balancing systems

03

A fully precomputed simulation engine — every outcome resolved into a replayable event log ahead of any rendering — with every tunable derived from formal analysis or empirical trials rather than guesswork.

combat.py

Deliberately asymmetric floor function, closing a guaranteed-loss edge case

Designed a single piecewise formula that provably eliminates an entire failure mode — no input combination can make one side's output ever floor to zero — while still permitting the inverse case on the receiving end. This is the kind of asymmetric invariant you reach for whenever a shared formula serves two roles that need different guarantees, worked out here as the core combat-resolution math.

damage = max(floor, ⌊ATK − 0.5 × DEF⌋), floor = 1 except when the defender is the player and attacker ATK is below a weak-attack threshold.
combat.py

Formal deadlock detection in a simulation loop

Traced a reported issue back to a real halting problem: a valid input state existed for which the simulation's core loop had no guaranteed termination condition. Rather than patch around individual causes, instrumented the loop itself with a general convergence check — N consecutive iterations producing zero state delta terminates the loop immediately — the same class of technique used to detect a stalled iterative solver, applied here to keep an edge case from becoming a multi-minute UI hang.

STALL_ROUND_LIMIT = 15, with explicit headroom verified against the longest legitimate windup mechanic in the game.
combat.py

Empirical parameter tuning via Monte Carlo–style trials

A parameter that resisted a clean closed-form justification was tuned the rigorous way: ran the simulation thousands of times per candidate value, measured the resulting outcome distribution against a target behavior, and iterated until simulated results matched intent — swapping a guessed constant for one backed by actual trial data before it ever shipped.

bonus_attacks = min(3, max(0, SPD_diff) // 3) — symmetric, applies to either side identically.
main_gui.py

A self-normalizing threshold function, derived from live input rather than hardcoded

Built a single parametric formula — reused across three interlocking rule instances forming a genuine cyclic dependency — where the trigger threshold for any one input is itself a function of the other two live inputs. The result is a system that provably can't be tripped by raw magnitude alone, only by imbalance between inputs, evaluated from one frozen snapshot per tick specifically to keep the cyclic dependency from producing order-dependent results.

effective_threshold = base + ⌊(other_stat_a + other_stat_b) / 2⌋ — recomputed from one frozen snapshot every frame to stay order-independent.
process

Data-driven tuning over intuition

Every numeric change to the simulation is gated on running the engine thousands of times across a matrix of input profiles and checking the resulting distribution against a target curve — the same methodology used to validate any statistical model before deployment — which caught at least one shipped-looking configuration that turned out to be a mathematically guaranteed degenerate case before it ever reached a real user.

Balance regressions caught pre-release: a 1-HP enemy variant found to be a mathematically guaranteed free kill, rebalanced before ever reaching a player.

Real-time interaction & custom scoring systems

04

Two real-time interactive systems built entirely from raw geometry, input events, and a custom scoring model — no game-engine physics or animation framework underneath either one.

main_gui.py — bone-dig puzzle

Ground-truth-vs-observation scoring model

Implemented a scoring system built on a deliberate separation between ground truth and observation: a hidden reference curve (a parametrically-generated, endpoint-tapered polyline — engineered specifically to guarantee a simple, non-self-intersecting path) drives live continuous distance-to-polyline scoring against user input, while the on-screen representation the user actually sees is never the thing being measured. This ground-truth/observation split is the same shape as any inference system that scores a model against labels the model itself never gets to see.

tight ≤ 10px · stray ≥ 26px, 9 consecutive stray samples fails the cut — graded Pristine only if ≥60% of samples land tight.
main_gui.py — bone-dig puzzle

State-machine design around a deliberate persistence asymmetry

Two interaction modes were engineered around opposite persistence guarantees on purpose: one holds zero retained state and derives its output purely from live cursor position every frame, the other commits every sample to a permanent, append-only record regardless of correctness. Getting this right meant explicitly reasoning about what should and shouldn't survive a state transition — validated with 3,000 fresh instantiations to confirm the generator itself never produces a degenerate or unwinnable configuration.

Verified with 3,000 fresh procedural-generation runs: zero exceptions, guaranteed minimum piece variety every run.
main_gui.py — boss encounter

Real-time interaction system with dynamically re-randomized target state

Built a full real-time input-timing system from primitives: a continuously-updating position function, a target-zone geometry that gets fully re-randomized on every single interaction (successful or not, to prevent the system from ever becoming learnable/memorizable), and a tiered difficulty function gated on a running performance counter rather than wall-clock time — deliberately isolated from every other subsystem in the codebase so it stands alone as a clean, self-contained module.

3 escalating cursor-speed tiers, gated purely on hits landed against the boss — not elapsed time.

Data-driven architecture

05

A content pipeline architected so the entire data model is external to the codebase — new content is a data-entry operation, never a code change, enforced by a shared resolution layer rather than convention.

enemy_db / item_db / shell_db / events

Full separation of content data from application logic

Architected the entire content layer — every entity definition the simulation operates on — as external tabular data rather than code, the same separation-of-concerns principle behind any real content-management or config-driven system. The application logic reads a schema; it never encodes a single specific entity by name.

10 CSV tables: enemies, items, effects, shells, events, event_effects, event_outcomes, landmarks, modifiers, bosses.
item_db.py / effects.csv

A single generic resolution layer, consumed by three independent call sites

Rather than writing three parallel implementations for three superficially different features, factored out one small, generic id → (key, value) resolution engine and had all three consume it identically — the textbook DRY (don't-repeat-yourself) refactor, but proven out here by three genuinely independent subsystems sharing one source of truth with zero duplicated logic.

effect_for_family/effect_for_shell both sum multiple IDs sharing a stat, rather than the later one silently overwriting the earlier.
item_db.py

Composable boolean-tag filtering over hardcoded conditionals

Replaced a pattern that scales linearly with content volume — a scattered set of hardcoded identity checks, one per special case — with a small set of composable boolean flags evaluated by one shared filter function. Adding a new special case now costs one flagged data field, not a new code path threaded through every consumer.

Multiple independent boss-exclusive drop pools share one small integer tag column rather than one bespoke system each.
rng_utils.py

A single generic algorithm, deduplicated across three call sites

Identified that three separate subsystems were independently reimplementing the same weighted-random-selection algorithm and consolidated them into one dependency-free, ~15-line utility module — a deliberate exercise in recognizing structural duplication and collapsing it to a single tested implementation rather than letting three near-identical copies drift out of sync.

Non-positive weights are silently excluded from the pool rather than raising — a 0%-chance category just never gets picked.

System architecture & coordination patterns

06

Coordination logic for state that has to reach back into already-completed computation, and for driving structurally unrelated subsystems through one shared interface.

combat.py / main_gui.py

Retroactive state mutation against an already-resolved computation, synced to a presentation layer

Engineered a mechanism to reach back into a fully-resolved, already-computed result set and apply a precise counterfactual correction — recomputing exactly what a specific input's removal would have changed to every downstream running total — entirely decoupled from, and computed before, any part of the presentation layer exists. The corrected result is then handed off to an independently-timed, multi-stage animation sequencer synced to the exact instant the underlying state actually commits — a clean separation between simulation correctness and presentation timing.

slide_in → fade_favor → hold → fade_sacrifice → hold → pop → fade_out → slide_out, each stage independently timed.
main_gui.py

An informal structural interface (duck typing), unifying five independent subsystems

Rather than build a bespoke dispatcher per interactive subsystem, defined one minimal structural contract — a small set of expected attributes, with no formal interface/abstract-base-class enforcement — that five completely unrelated subsystems each independently satisfy. One generic dispatcher then drives all five without ever branching on which one it's looking at: textbook polymorphism via duck typing, applied to keep the addition of a sixth subsystem a zero-touch integration.

A brand-new encounter type becomes drop-in compatible with the existing UI the moment it implements that one shared shape.
main_gui.py

Idempotent per-frame resync, replacing an event-driven mutation graph

Rather than hook every individual mutation site for a piece of derived state — a pattern that scales combinatorially and is a classic source of ordering bugs — implemented a pure, idempotent recomputation function that re-derives all dependent state fresh from a single immutable snapshot every tick. This sidesteps an entire category of stale-state and update-ordering bugs by construction, including a case with a genuine circular dependency between three interacting values.

Three debuffs form a real dependency cycle (DEF→SPD→ATK→DEF) and still resolve deterministically every frame.

Engineering process & rigor

07

The mechanics above didn't ship as a single build — they came out of a disciplined, self-imposed process, documented as thoroughly as the code itself.

DOCS

Maintained a full decision log across 68 discrete engineering iterations spanning roughly 2.5 weeks — every entry records the problem, the alternatives considered, the chosen approach's rationale, and quantified before/after results, the same discipline as an internal RFC or ADR (architecture decision record) process.

TESTING

Built a fully headless automated test harness — no display or audio hardware required — that exercises real, live instances of every subsystem end-to-end rather than mocking dependencies, the same "test the real thing" philosophy behind integration testing over pure unit testing.

SAFETY

Enforced a byte-for-byte diff-before-overwrite protocol on every delivered change against the live working copy, both before and after — a manual analogue to the conflict-detection a version-control system provides automatically, applied here without one in place.

ARCHIVE

Treated design rationale as a first-class deliverable, not a byproduct — systematically extracting implementation reasoning out of inline comments and into a permanent, independently-readable technical record, so institutional knowledge survives independently of any single reading of the code.
